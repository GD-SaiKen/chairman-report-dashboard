# 公司 AI 驾驶舱第二阶段：HTML 报告导入与审核发布设计

## 1. 目标

第二阶段把当前依赖人工准备 JSON 的静态驾驶舱升级为受控的线上报告导入系统。信息部可在统一 Basic Auth 保护下，通过不出现在普通导航中的管理入口，为一个期次上传多份 HTML 报告；系统从报告中提取公司 AI 普及、部门使用、需求、Skills/Agents、Token 和前沿雷达信息，经过人工审核后生成并发布正式周快照。

本阶段只从上传的 HTML 报告提取信息，不接入实时数据库、业务 API、日志平台或消息推送系统。

## 2. 范围

### 2.1 本阶段包含

- 一个期次上传多份 `.html` 或 `.htm` 报告。
- 为每份文件登记报告类型、标题和来源部门。
- HTML 安全清洗、结构化分块、规则提取和 AI 语义归类。
- 部门、人员、需求、能力、Token、雷达和报告入口的草稿生成。
- 原文证据、置信度、冲突和质量警告展示。
- 人工修订、确认和正式发布。
- 发布前差异预览、完整校验和原子切换。
- 发布历史和上一版本回滚。
- 服务重启后的草稿与任务恢复。

### 2.2 本阶段不包含

- 实时数据库、业务 API 或日志数据源接入。
- PDF、Word、Excel、图片或压缩包导入。
- 独立账号体系、角色权限或上传专用密码。
- 自动向钉钉、邮件或其他渠道推送异常。
- 默认每日视图或实时刷新。
- 金额收益、节省工时和员工绩效评估。

## 3. 总体架构

现有原生 ES Module 前端和 JSON 快照结构继续保留。`server.mjs` 从只读静态服务器升级为带受控写入 API 的 Node.js 服务；Nginx Basic Auth 继续作为站点统一访问门禁。

```text
Nginx Basic Auth
        │
        ├── /                         公司 AI 驾驶舱，只读
        ├── /reports/...              已发布报告全文
        ├── /manage/import            掩门上传与审核工作台
        └── /api/import/*              上传、解析、审核、发布 API
                    │
                    ├── storage/uploads/   原始上传件
                    ├── storage/drafts/    草稿、任务和修订记录
                    └── data/snapshots/    正式周快照
```

`/manage/import` 不进入侧栏或普通页面链接。它只降低误触，不构成额外安全边界；页面、管理入口、API、快照 JSON 和报告全文均由同一 Basic Auth 保护。

## 4. 用户流程

### 4.1 创建期次

管理员输入期次 ID、展示名称、数据窗口和截至时间。期次 ID 使用 `YYYY-MM-DD`，且不得与已发布期次重复。已有草稿允许继续编辑，已发布期次只能通过“创建修订版”更新。

### 4.2 上传多份报告

一个期次可上传多份 HTML。每份文件必须填写：

- 报告标题
- 报告类型：信息部周报、项目报告、部门报告或其他
- 来源一级部门
- 是否作为正式报告全文发布

系统显示文件摘要、大小、编码、内容哈希和重复状态。相同哈希文件不得重复加入同一草稿。

### 4.3 自动解析

解析任务按以下顺序执行：

```text
文件检查
→ HTML 安全清洗
→ 标题、章节、表格、列表和链接分块
→ 规则提取明确数字与字段
→ AI 对净化文本进行语义归类
→ 合并同一期多份报告
→ Schema 与业务口径校验
→ 生成待审核草稿和质量报告
```

### 4.4 人工审核

工作台分为四步：

1. 文件检查：确认文件身份、编码、重复文件和清洗结果。
2. 提取预览：按部门、需求、能力、Token、雷达查看提取值与原文证据。
3. 质量处理：解决未知部门、数字冲突、重复需求、Token 口径冲突和缺少证据。
4. 发布确认：查看相对上一已发布期次的新增、修改、删除和质量变化。

审核人员可以修改结构化值，但不能改写原始证据。每次修改记录字段、旧值、新值、时间和操作者标识；本阶段操作者标识由管理工作台要求手工填写显示名，不引入账号体系。

### 4.5 发布与回滚

发布时先在临时目录生成全部专题 JSON、质量报告、清洗后的报告全文和新版 manifest。只有所有 Schema、引用路径和文件完整性检查通过后，服务端才通过目录重命名进行原子切换。

发布历史保存：

- 发布 ID 和时间
- 期次 ID
- 操作者显示名
- 输入文件名与 SHA-256 摘要
- 规则版本和模型标识
- 输出文件摘要
- 校验结果

回滚不是重新解析，而是把某个已发布版本重新设为当前版本，并恢复对应 manifest 和报告目录。

## 5. 混合提取设计

### 5.1 安全清洗

上传的 HTML 一律视为不可信输入。服务端解析时：

- 删除 `script`、`iframe`、`object`、`embed`、`form` 和 `base`。
- 删除 `on*` 事件属性、`javascript:` URL、自动刷新和内联脚本。
- 不加载外部字体、图片、样式或其他网络资源。
- 将相对链接解析为报告内相对路径，不主动访问目标地址。
- 对隐藏文本、超长节点和可疑凭据模式生成质量警告。

AI 只接收净化后的文本块以及必要的表格结构，不接收脚本、隐藏字段、注释或原始二进制附件。

### 5.2 规则提取

规则层优先提取确定性信息：

- `h1` 至 `h6` 标题和章节层级
- HTML 表格的表头、行和单位
- 列表、数字、百分比、日期、人员名和部门名候选
- Skills、Agents、Token、需求、风险、决策等关键词附近的上下文
- 报告标题、窗口、更新时间和原始链接

规则结果保留 DOM 定位路径、章节标题和原文片段，作为后续追溯证据。

### 5.3 AI 语义归类

AI 层通过可替换的 `ExtractionProvider` 接口工作，输入为受大小限制的净化文本块，输出必须符合严格 JSON Schema。AI 可提出：

- 一级部门映射候选
- 实名人员与团队候选
- 需求主题、频次和漏斗状态候选
- Skill、Agent、自动化任务和运行结果候选
- Token 记录分类和来源候选
- 雷达候选及公司适用性草稿

AI 不得自动做以下决定：

- 把需求标记为已方案化、已交付或已复用
- 把工具调用次数认定为成功产出
- 合并不同来源、不同口径的 Token 总量
- 把雷达候选直接发布为正式条目
- 基于 Token 或使用频次推断员工绩效

### 5.4 证据模型

每个提取字段保存：

```json
{
  "sourceFileId": "file-01",
  "sectionTitle": "AI 使用情况",
  "locator": "body>main>section:nth-of-type(3)>table",
  "excerpt": "信息部本期活跃用户 2 人……",
  "method": "rule",
  "confidence": 1,
  "reviewStatus": "pending"
}
```

AI 提取项的 `method` 为 `ai`，置信度只用于审核排序，不能绕过人工确认。

## 6. 合并与业务口径

### 6.1 部门与人员

部门映射优先使用 `data/curation/{period}.json`，其次使用已审核的公司部门字典。无法唯一映射的部门进入质量警告，不自动创建正式一级部门。

同一实名人员只有在标准化姓名、来源部门和可用标识能够一致时才合并。不能确认时保留为不同候选并要求人工处理。

### 6.2 需求

相同人员、相同来源、标准化文本前 150 字一致的重复回放自动折叠。跨部门或跨报告的相似需求仅标记为“可能重复”，由人工决定是否合并。

需求状态只能由报告中的明确证据或人工审核确定。`closed` 可从任一未完成状态进入；其他状态必须按 `captured → assessed → designed → delivered → reused` 顺序推进。

### 6.3 Skills、Agents 和自动化

能力资产按规范化名称、类型和责任团队识别。执行次数与成功产出分开计算。只有存在交付物 ID、可访问报告证据或明确的 `deliveryStatus: sent` 才计为成功产出。

### 6.4 Token

继续沿用第一阶段口径：

```text
Sino WebUI       → 员工 WebUI 主口径
Cursor / CLI     → 信息部或项目口径
Agent / cron     → 能力资产口径
aikey gateway    → 对账口径，不加入业务总量
```

有效消耗、缓存读取、非业务消耗和对账量分别存储与展示。缺少来源、分类或时间窗口的 Token 数字不能进入正式汇总。

### 6.5 雷达

报告中出现的 AI 工具、智能体工具和话题只作为候选。正式发布前必须补齐公司适用性、风险和信息部结论，结论仅允许：关注、安排试用、建议引入、暂不采用。

## 7. 存储和状态

导入任务状态固定为：

```text
uploaded → sanitizing → extracting → validating → review_required → approved → publishing → published
```

任一处理中状态可进入 `failed`。失败记录包含阶段、可公开错误摘要和服务端诊断 ID；诊断信息不得包含模型密钥、Basic Auth 凭据或完整敏感原文。

草稿采用服务器文件系统持久化，使用 JSON 索引和内容寻址文件，不引入数据库。该选择适合当前单站点、低并发、周度上传场景，也保持部署复杂度可控。若后续需要多人并发审核或每日运行，再迁移到数据库。

## 8. API 边界

本阶段提供以下服务端接口：

```text
POST   /api/import/periods                     创建期次草稿
POST   /api/import/periods/:id/files           上传一份 HTML
POST   /api/import/periods/:id/extract         启动或重试解析
GET    /api/import/periods/:id                 读取任务与草稿状态
PATCH  /api/import/periods/:id/draft           保存人工修订
POST   /api/import/periods/:id/approve         确认审核完成
GET    /api/import/periods/:id/diff            读取发布差异
POST   /api/import/periods/:id/publish         原子发布
GET    /api/import/releases                    发布历史
POST   /api/import/releases/:releaseId/rollback 回滚版本
```

所有写接口校验 `Origin`、请求方法、内容类型和一次性 CSRF Token。Basic Auth 相同不代表可以省略浏览器侧请求伪造防护。

## 9. 错误处理

- 非 HTML 扩展名、MIME 不符、超限文件或空文件在上传阶段拒绝。
- 编码无法识别时要求用户选择编码后重试，不猜测发布内容。
- 单份报告解析失败不阻止其他文件完成，但草稿保持不可发布状态，直到失败文件被删除或成功重试。
- AI 输出不符合 Schema 时自动进行一次结构修复；仍失败则保留规则提取结果并进入人工处理。
- 多来源数字冲突显示所有候选、证据和来源，不默认取最大值或最新值。
- 发布校验失败时删除临时产物，保持当前线上版本和 manifest 不变。
- 回滚失败时保持当前版本，不执行部分覆盖。

## 10. 测试策略

### 10.1 单元测试

- HTML 清洗与危险节点删除
- 编码、大小和 MIME 校验
- 章节、表格和数字分块
- AI JSON Schema 校验和失败回退
- 部门映射、需求去重、能力产出和 Token 口径
- 草稿状态机和发布权限条件
- 差异计算和发布清单摘要

### 10.2 集成测试

- 一个期次上传多份 HTML 并合并生成草稿
- 服务重启后继续读取任务和草稿
- 数字冲突与未知部门阻止发布
- 人工修订后重新校验并发布
- 临时目录生成失败不改变线上版本
- 发布后 manifest、六个专题和报告全文同步可用
- 回滚恢复上一版本

### 10.3 浏览器验收

- 桌面、960px、720px、420px 完成上传、审核和发布流程
- 任务进度与失败状态可读，不只依赖颜色
- 表格和差异视图可横向滚动
- Escape、焦点恢复和读屏播报正常
- 掩门不出现在驾驶舱导航或站点地图

## 11. 部署与运维

- Node 服务拥有 `storage/`、`data/snapshots/`、`reports/` 和 manifest 发布目录的最小写权限。
- Nginx 限制请求体大小，并对 `/api/import/` 关闭静态缓存。
- 模型密钥通过环境变量提供，日志只能记录模型标识和请求 ID。
- `storage/`、临时发布目录、上传文件和环境变量文件全部加入 `.gitignore`。
- 备份必须同时覆盖已发布版本索引、快照和报告目录，确保回滚引用完整。
- 发布前继续扫描密钥、令牌、密码、公网 IP 和 `.env`，并确认上传原文没有被 Git 跟踪。

## 12. 成功标准

- 信息部能在线创建期次并上传多份 HTML 报告。
- 自动生成覆盖六个驾驶舱专题的结构化草稿。
- 每个正式数字和状态可追溯到报告原文或人工审核记录。
- 数字冲突、未知部门、重复口径和缺少证据不会静默发布。
- 审核前不改变线上数据，发布时不会出现半成品。
- 发布后默认期次、六个专题和报告全文同步更新。
- 可查看发布历史，并将站点完整回滚到上一已确认版本。
